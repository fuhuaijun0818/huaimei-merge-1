# 共同交付规范

三人均从 `team-baseline-20260910-v2` 开始；只向负责人交付，不自行部署或合并他人代码。基线提交号见仓库标签及分发包 BASELINE-RECEIPT.json。V2继承V1协作历史，V1与原工作目录是独立 Git 历史，交回的代码统一合入负责人保留的 integration-repo，不直接与原工作目录的历史混合。

## 开始开发

安装 Git、Node.js 22+，在基线包所在目录执行：
```
git clone huamei-baseline-v2.bundle huamei-work
cd huamei-work
git switch -c feature/A/dialogue-001 team-baseline-20260910-v2
npm ci
npm --prefix apps/acquisition-advisor ci
npm run team:init
npm run team:build
npm run dev
```
将 A/dialogue-001 换成自己的角色和任务号。访问 http://127.0.0.1:4173/advisor/ 和 /login。初始化脚本只在本机生成独立开发账号和密码；配置不提交。不同电脑可使用相同端口，同一电脑用独立副本并自定PORT、HUAMEI_ACQUISITION_SERVICE_PORT与HUAMEI_ACQUISITION_SERVICE_URL；同时把新的网页源加入HUAMEI_ALLOWED_ORIGINS，否则浏览器请求会被拒绝。

默认禁用外部模型、会员接口、GraphRAG和自动外发；语义模型需要开发者自己的配置。保留正常账号登录与权限校验；不能为了演示删除权限检查。开发知识包为924条现有公开记录子集，完整原始资料、客户记录、正式发布状态不在分发包内。依赖完整私有资料或真实服务的测试应标记blocked并写明原因，不能当作pass。

## 修改约束

以 ownership.json 为文件归属依据。现有后台页面和路由仍有集中大文件，本次未做大规模抽取。A可直接开展对话工作；B/C在src/modules和server/routes新增独立模块，共用入口注册改动单独提交，在shared_changes中列出。不能按目录通配符把另一人的专属文件覆盖；更具体路径优先。

共用接口以contracts里的现有OpenAPI快照和真实服务代码为参考，两者不一致时先报告；不得仅修改快照伪装兼容。任何字段删除、重命名、鉴权或业务状态语义变更都须明确列出。已有数据库迁移不可修改；新增迁移先使用开发临时文件，交付时列出，由负责人统一编号。依赖变化同时交付对应锁文件。

业务口径：手机号格式通过后保存，不加OTP；院方查询true=已有记录、false=未找到，错误/未查/超时独立表示。模型不能伪造保存、预约或付款成功。人工接管时AI不能抢答。知识正式发布与权限边界不能绕过。

## 交付

一项功能一条短期分支，建议1～2个工作日交付一次。保留完整提交历史，禁止重写共同基线。共享文件修改在报告里申报，不需要自行合并他人分支。

1. 完成模块测试及 `npm run team:verify`；真实接口/数据库未具备时记录blocked。
2. 复制 `handoff/report-template.json`，填写任务、测试、共享变更、迁移、依赖配置变化、复现步骤、回退和限制。
3. 保存为如 `handoff/report-A-dialogue-001.json`，代码和报告一起提交，保持工作区干净。
4. 执行：
```
npm run team:deliver -- --role A --id dialogue-001 --report handoff/report-A-dialogue-001.json
```
5. 把 `.team-delivery/A-dialogue-001/` 内全部文件压缩后交给负责人：增量bundle、manifest、report、checksums。manifest绑定基线提交、交付提交、文件增删改与哈希；测试结果来自开发者报告，不冒充自动认证。

严禁提交`.env.local`、真实密钥、客户聊天、数据库转储、node_modules、构建缓存；测试只用模拟客户。交付脚本检查常见泄露模式，但不能替代人工审查。

## 负责人接收

先核对外层校验和，在保留的integration-repo内执行`npm run team:inspect -- /绝对路径/manifest.json`。该步骤校验交付标识、基线、bundle和文件清单，导入到incoming引用但不合并、不执行收到的代码。

审查改动及共享文件、依赖和迁移后，在临时验收分支合并并运行隔离测试；合格才合入integration/huamei-vnext。不得自动运行来路不明的脚本。出现冲突按业务需求核对，禁止一律选择ours或theirs。交付只包含相对初始基线的增量，因此负责人必须保留基线仓库或同一baseline.bundle。

验收链路：前台咨询→留资与会员状态→后台同会话→人工接管及回复→预约更改→知识发布和撤回→各岗位数据权限。

V2新增devkit/、contracts/dev-v2/、tests/onboarding/由负责人维护；.team-dev禁止交付。V1交回代码先在保留的V1仓库验收，再由负责人迁移；不能移动V1标签或假改交付清单。
