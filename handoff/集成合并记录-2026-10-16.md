## 3. 共享文件冲突与采用方案

冲突集中在共用入口（`src/app.js`、`src/subpages.js`、`server/api-router.mjs`、
`apps/acquisition-advisor/src/App.jsx`）与共用测试，按 `handoff/ownership.json`
的“共享优先、具体路径优先”判定归属，逐个核对业务意图后合并，未使用整文件覆盖。

| 文件 | 冲突 | 采用方案与理由 |
|---|---|---|
| `server/api-router.mjs` | 5 处 | 人工回复只保留 **B** 的 `POST /api/admin/acquisition/conversations/:id/reply`。A 曾平行新增 `POST /api/admin/acquisition/handovers/:id/reply`，两条路由做同一件事、各带一套鉴权与写入实现；按《共同交付规范》“不得复制第二套鉴权、路由或状态存储”，且 B 的实现具备幂等键、接管版本校验、送达回执与 PostgreSQL 持久化，管理端 `src/operations-client.js` 调用的也是 B 的入口。A 的 `/acquisition-chat/stream`、`/acquisition-conversation`、`/acquisition-upload`、反馈 405 收口与 B 的 `/acquisition-history`、`/acquisition-deliveries`、读回执全部保留。 |
| `server/api-router.mjs` | 管理审计门禁 | 采用 **B** 的 `if (!postgresPersistenceEnabled()) return;`。C 的 `managementAuditPersistenceEnabled`（`HUAMEI_LOCAL_MANAGEMENT_AUDIT_ENABLED` 开关）会让隔离 PostgreSQL 静默不写管理访问审计，与 `tests/management-authorization.mjs`“隔离 PostgreSQL 也必须写审计”的要求冲突，故弃用该开关。 |
| `apps/acquisition-advisor/src/App.jsx` | 10 处 | 以 A 的顾客端重写为骨架（流式、上传、重试/停止、草稿与滚动、媒体失效原因），叠加 B 的能力：预约留资提示与项目补录、手机号 `+86/0086` 归一校验、人工顾问气泡、服务端整段答复与本地分段气泡对账（`serverReplyId` + `mergeReplySegments`）、乐观消息用同一个 `message_id` 做幂等。**会话消息统一由 `/api/public/acquisition-history` 回读**（含人工回复与游标），A 的 `/acquisition-conversation` 仅用于取上传能力位并续签会话凭证，避免两套消息来源并用。A 被取代的 `transcriptMessage`/`isRenderedAlready` 已删除，未留死代码。 |
| `src/app.js` | 6 处 | 回复草稿（B）与知识筛选状态（C）为不同功能，二者并存；`encodeAcquisitionCursors` 的闭合括号按两侧结构补齐。接待页采用 B 的版本（`customerDisplayName`、分页加载、`data-action="conversation-detail"` 有处理器）。知识治理页采用 **C** 的调用方式 `knowledgeIntakePanel()`（面板自身处理“功能关闭/无权限/无数据”三态，见 C-017 AC4），同时保留 A 的 `qualityRedactedConversationPanel()`。引导流程保留 B 的身份与已读回执初始化、写入闸门 `managementDataReady=handoverOnlyMode`，并补上 C 的 `setIdentityCapabilities()`。 |

`/conversations/:id/reply` 发送人工回复（幂等键重放不产生第二条）→ 顾客端
`/acquisition-history` 读到人工顾问消息 → `/acquisition-deliveries` 确认送达（重放幂等）→
历史再次查询显示已送达。同时验证 A 的能力位回读、上传开关关闭时返回 403
`CUSTOMER_UPLOAD_DISABLED`、反馈接口非 POST 返回 405、任意形状的资料链接返回 404 而非
“缺少 X-API-Key”。

## 6. 复现步骤

```powershell
# 从交付包克隆
git clone --branch integration/huamei-vnext huamei-integrated-vnext-20261016.bundle huamei-integrated
cd huamei-integrated
git rev-parse integration/huamei-vnext      # 应为集成标签指向的提交

npm ci
npm --prefix apps/acquisition-advisor ci
npm run team:build
npm run team:verify
npm run team:test:http

# 起本机真实应用
npm run team:init      # 生成本机单账号开发配置（不提交）
npm run dev            # 前台 http://127.0.0.1:4173/advisor/ ，后台 /login
```

依赖安装必须走锁文件，不依赖个人电脑的残留包。`.env.local`、`.team-dev`、`.local-data`、
数据库转储与真实账号不进入交付包。
