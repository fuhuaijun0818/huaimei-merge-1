## 问题 1：正式发布"激活"被数据库约束拦住（阻塞 AC4 的 Postgres 复现）

- 现象：正式流程（草稿 → 业务/医务/合规三次实名审核 → 索引绑定 → 激活）前三步通过，激活报
  `23514 GraphRAG manifest is not bound to the approved release`。
- 含义：约束要求绑定的索引清单与本次批准发布一一对应（正式 GraphRAG 索引产物）；本机 GraphRAG
  显式关闭（`GRAPHRAG_EXPLICITLY_DISABLED`），没有正式索引可绑。
- 影响：Postgres 下无法产生"生效发布"→ enforce 时知识面 fail-closed；preview 下发布范围不参与
  检索，因此"撤回后不再引用"在该模式无法演示。
- 待决策（融合后）：① 用官方 GraphRAG 索引管线产出索引并在绑定时写入与发布对应的 manifest；
  ② 或给开发实例放宽该约束（仅生产环境强制）；③ 或接受"AC4 以本地 JSON 证据记账"。
- 复现：`node .team-dev/c-verify-a014-ac4-pg.mjs`（Postgres 版，当前卡在激活）；
  `node .team-dev/c-verify-a014-ac4.mjs`（本地 JSON 版，已通过）。

### 当时的分步方案（已按此实施，保留备查）

**AC2（启用上传时限制类型/大小并显示失败重试）——需新增上传能力**

1. 服务端：新增公开上传接口 `POST /api/public/acquisition-upload`
   - 会话凭证绑定（复用 `resolvePublicSession`）、限流、幂等键；
   - JSON 体 `{ file_name, mime_type, data_base64 }`，白名单：jpg/jpeg/png/webp/pdf；
   - 大小上限（图片 64MB / PDF 32MB，与 `knowledge-media.mjs` 的公开素材阈值一致），超限/类型不符返回明确错误码；
   - 落盘到 **客户专属目录** `.local-data/customer-uploads/<tenant>/<session>/`（绝不放 knowledge/ 或公开素材包）；
   - 由 `HUAMEI_CUSTOMER_UPLOAD_ENABLED` 控制是否启用（**代码默认 false**，只有显式置 true 才暴露上传能力），并经能力接口暴露给前台。
2. 前台：附件按钮（能力关闭时不渲染 —— 保持 AC1 的"不留无效入口"）、选择时先做类型/大小前置校验、上传失败显示"重试"、成功后作为**客户侧附件气泡**展示（不进入知识引用）。
3. 验收用例：类型不符被拒、超限被拒、正常上传成功、网络失败后可重试成功、能力关闭时无按钮且追问得到"未启用"话术。
