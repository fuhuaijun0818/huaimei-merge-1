# 留资后院方查询接口接入

## 当前启用状态（2026-09-08）

院方查询适配器已在本地开发环境启用并通过真实请求验证。地址为 `https://scrm.shhmwz.cn/api/thirdApi/checkPhoneExists`，POST JSON，方法标识 `meb.sync.client.repeatcheck`。就绪状态为 `enabled=true`、`ready=true`。

当前使用 `provided_headers` 兼容模式：仅在服务端私有环境保存用户提供的完整签名头，不需要另配 MEB secret。已对授权号码 `176****2501` 多次真实查询，返回 `isSuccess=true`、`isRepeat=false`。这只能证明查询时现成签名有效，不能保证长期有效，也不代表接口无需签名。

网页留资不再接入短信验证码。用户提交格式有效的11位中国大陆手机号并同意本次咨询联系后，系统立即保存线索，将手机号标记为“待人工核号”，并尝试调用院方查询接口。销售顾问在后续回电中人工核对手机号。

`isRepeat=false` 表示院方未查到重复记录。接口是否可直接代表会员资格仍需院方确认，所以当前 `member_status=unknown`，后台显示“院方未查到重复记录，会员身份待确认”，不会标记为非会员。

## 自动处理流程

1. 用户提交手机号并同意本次咨询联系；服务端校验11位中国大陆手机号格式。
2. 格式通过后立即创建或更新客户档案、加密保存联系方式、标记“待人工核号”，并自动查询院方接口。查询绑定当前手机号、租户和会话。
3. 将规范化结果保存到 `customer.memberCheck`。管理端客户画像展示“院方身份核验”及查询时间。
4. 查询失败、签名失效或超时不阻断有效留资，查询结论保持未知。再次有效提交会重新尝试；成功结果默认复用 60 秒。院方查重不等于手机号本人认证。
5. 客户侧留资回执不返回查重结果、会员状态或是否已有客户，避免通过回执探测他人信息。

## 服务端配置

配置在被 Git 忽略、权限为 0600 的 `.env.local`。凭据不得进入前端、源码、诊断日志或客户档案。`.env.example` 仅提供无凭据模板。

| 配置项（统一前缀 `HUAMEI_MEMBER_CHECK_`） | 说明 |
|---|---|
| `ENABLED` | 运行开关，当前本地为 true |
| `AUTH_MODE` | 默认 md5；当前本地为 provided_headers |
| `URL`、`HTTP_METHOD`、`TENANT_ID` | 服务端固定地址、POST、绑定租户，浏览器不能覆盖 |
| `AKEY`、`TOKEN` | 私有请求头；当前 token 为空 |
| `PROVIDED_TIMESTAMP`、`PROVIDED_NONCE`、`PROVIDED_SIGN` | 一套完整的现成签名头，不能只改其中一个值 |
| `SECRET` | 仅 md5 模式所需的院方配套 secret，不得用 akey 代替 |
| `OPERATION` | read_only，本次按用户授权的号码查询操作接入 |
| `RESULT_SEMANTICS` | 当前 duplicate_only；院方确认会员映射前保持该值 |
| `TIMEOUT_MS` | 整体超时涵盖签名、请求、响应体，最大 5 秒 |
| `CACHE_MS` | 默认 60000，最大 300000；0 禁用缓存；凭据轮换会使缓存失效 |

`provided_headers` 只允许显式 development 环境及本次已验证的 scrm 精确地址，不允许生产环境使用。正文只传 `phone:[号码]` 和与签名头一致的 `timestamp`，不复制示例姓名、微信、跟进信息。签名失效时不自动尝试其他凭据。

`md5` 模式按已提供截图规则连接 `akey`、`method`、`timestamp`、`token`、`secret`、`nonce`，使用 `&`、保留空的 `token=`，以 UTF-8 计算 MD5 并输出 32 位小写十六进制。每次生成新时间戳和 nonce，secret 不随请求发送。该算法已通过固定夹具测试，尚未取得院方 secret 完成真实动态签名验收。切换或轮换配置后需重启服务。

## 校验与失败行为

只接受 HTTP 成功、`isSuccess === true`、恰好一条记录、号码精确匹配且 `isRepeat` 为布尔值的响应。拒绝重定向、超过 16 KB 的响应、无效 JSON、错误号码和字符串布尔值。并发同客请求合并，失败不缓存为成功。

| 状态 | 管理端含义 |
|---|---|
| not_configured | 待接入院方接口 |
| capture_required | 手机号尚未有效保存 |
| failed | 核验未完成，待重试 |
| checked + duplicate_only | 院方已有记录 / 未查到重复记录，会员身份待确认 |

记录仅含规范化状态、错误码、时间、查重布尔值、认证模式和不可逆配置指纹，不含手机号原文、akey、secret、token、nonce 或 sign。

## 验证证据

- 60 项默认回归全部通过；离线服务测试显式禁用真实院方查询。
- 新增兼容模式的签名头传递、最小正文、配置缺失、生产拒绝、精确地址限制、凭据轮换、零缓存和签名失败测试。
- 真实流程：未验证留资 HTTP 202 → 模拟验证码挑战 201 → 模拟验证通过 200 → 留资 200 → 真实院方查询成功 → 客户档案保存 → 管理端读取一致。客户侧无会员结果，档案无原始手机号或凭据。
- 联调独立临时数据目录已删除，未往当前应用业务数据中写入测试客户。
- 首轮真实流程的院方请求与保存成功，但验证脚本误以为带“测试”姓名的新档案会自动排除；纠正脚本后复验通过。未改动现有客户分类规则。
