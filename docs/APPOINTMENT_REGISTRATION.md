# 到院登记实现与部署说明

基线：华美一期售前智能体详细 PRD V1.4、用户已确认的“手机号只做格式校验，销售回电人工核号”规则。更新：2026-09-09。

## 客户和顾问的操作

1. 客户在咨询中提出到院需求，保存有服务联系授权的格式有效手机号。
2. 登记表明确展示院区、咨询项目或医生；客户选择完整日期以及日期/半日/分钟精度，并主动确认摘要。
3. 系统直接生成唯一登记号，状态 `registered`，手机号状态 `pending_manual`。登记不锁定医生或接诊名额。
4. 顾问在工作台领取跟进，当前领取人可一次性查看回拨号码、填写跟进说明。查看后30秒自动隐藏；只有数据库模式提供完整披露审计。
5. 客户凭当前有效会话可恢复登记、改期或取消。改期沿用登记号和同一跟进任务；取消后退出待跟进队列。原待处理通知失效。

客户操作和顾问跟进是两套状态。顾问完成跟进不改变客户登记结果，后续客户改期会重新打开跟进。已取消登记或已结束跟进不能继续查看回拨号码。联系授权失效或限制联系生效也会拒绝披露。

## 数据与并发约束

- 数据库迁移 `014_appointment_registration.sql` 新增 `appointment_sessions`。按租户及渠道/会话摘要分区；每会话加行锁，保证同一会话至多一条有效登记。
- 登记、确认摘要指纹、幂等回执、跟进任务、待处理通知在同一密文载荷内提交；审计事件与其使用同一数据库事务。
- 相同幂等键与相同内容重放；不同内容冲突。客户改期/取消必须提交 `expected_version`，旧版本不能覆盖新版本。
- 普通列表与客户响应不携带明文号码。客户响应额外去除内部确认信息、领取人和跟进备注。号码披露另走权限、归属、有效授权、限制联系、一次性请求及审计检查。
- 联系方式查询同时支持会话内部标识与外部标识，结果不唯一时不建立关联。不会凭浏览器声称“已留资”放行。
- 生产环境要求 PostgreSQL 与既有字段加密、独立联系方式密钥域；禁止降级使用本地预约 JSON。生产登记表已加入对象权限白名单、FORCE RLS、发布预检和备份关键表清单。
- 通知当前为 `manual_required`，未连接真实通知发送器。没有将“已登记”写成“已送达”。真实发送器接入时必须在发送前复核最新登记版本、联系授权和服务归属。

## 日期规则

所有业务日期采用 `Asia/Shanghai`。拒绝含糊日期、非法日期、过去时间；今天到院必须选择未来的具体钟点。未来日期可只确定日期或保留上午/下午/晚上，不擅自补钟点。

`HUAMEI_WORKDAY_CALENDAR_FILE` 可指向受维护的工作日日历 JSON。需包含 `version`、`source`、`maintained_by`、`coverage_start`、`coverage_end`、`expires_at` 和日期到布尔值的 `overrides`。默认周一至周五，调休和节假日通过覆盖项表达。该文件应来自院方确认的日历数据，不能把测试夹具部署为正式日历。

建议日期从明天开始，仅在有效日历覆盖内返回两个工作日。文件缺失、损坏、过期、覆盖不足或元信息不完整时返回空建议，由客户自主选择。客户已选日期不被建议覆盖。

## API

| 方法与路径 | 作用 |
|---|---|
| GET `/api/public/appointment-dates` | 工作日建议或自主选择降级 |
| POST `/api/public/appointment-intakes` | 客户确认后登记，返回 `intake` 与会话凭证 |
| POST `/api/public/appointment-intakes/current` | 使用会话凭证恢复本人当前/最后一条登记 |
| POST `/api/public/appointment-intakes/{id}/reschedule` | 带版本、确认和幂等键改期 |
| POST `/api/public/appointment-intakes/{id}/cancel` | 带版本、确认和幂等键取消 |
| GET `/api/admin/appointment-intakes` | 管理身份范围内的登记列表 |
| POST `/api/admin/appointment-intakes/{id}/claim` | 领取跟进 |
| POST `/api/admin/appointment-intakes/{id}/resolve` | 记录 `completed` 或 `needs_customer_info` 与说明 |
| POST `/api/admin/appointment-intakes/{id}/contact-reveal` | 当前领取人一次性查看回拨号码 |

旧排班写端点返回410，旧排班读端点只返回空列表。OpenAPI同步了新语义，不能继续按旧 `pending → confirmed + schedule_slot_id` 流程调用。

## 升级、恢复与限制

- 正式升级先停止写入并完成备份，使用迁移账号执行001–014，再运行对象权限归一和发布预检。运行账号没有DDL权限。
- 新本地文件为 `.local-data/appointment-registrations.json`，仅供开发。原 `.local-data/appointment-intakes.json` 不删除、不自动把旧排班申请转成客户已确认登记。本次检查未发现默认路径的旧文件；其他部署若有历史数据，须先清点并形成迁移与客户重新确认方案。
- 回滚应用前核对接口版本：旧应用不能正确解释新版登记，不能仅切换镜像后继续接受写入。保留新表数据并暂停写入，再按审批的恢复方案处理。
- 列表当前最多500条，工作台取最近200条。列表统计不是全量历史经营指标。
- 会话凭证过期后不允许仅凭手机号恢复历史登记；由人工按授权流程处理。刷新恢复不等于长期账户登录。
- 导出、删除仍使用现有人工隐私执行计划；执行范围必须包含新增登记、跟进、回执和通知，不能只处理线索表。真实外发尚未启用。

## 已执行验证

本地领域测试覆盖确认、严格日期、调休日历降级、幂等冲突、竞争领取、改期取消、版本冲突和回滚。真实隔离 PostgreSQL 测试覆盖20路并发、加密、RLS、重连恢复、授权失效和号码披露限制。API测试覆盖留资到登记、后台处理、会话恢复、跨会话拒绝、新对话隔离。

浏览器在隔离4177服务中完成登记、刷新恢复、改期、领取、查看测试号码、跟进、取消及重置后刷新；外部模型和会员请求关闭。浏览器验收使用虚构测试数据，未进行真实外呼、短信或渠道发送。
