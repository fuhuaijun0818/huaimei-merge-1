## 阅读与执行

用户真实坏例优先：一般原理追问、抗衰主诉、姓名电话主动提交、输入框失焦。A负责理解和对客体验，B负责业务保存/接管/预约权威，C负责知识有效性。

每条均为目标验收要求，不代表当前全部未实现。先运行/复现并记录“已有通过、需修复、需新增、受阻”；已有能力应复用。AC1～AC4是独立验收点，代码入口是本次核对存在的定位参考，不表示该功能已完整实现。协作依赖含联合验收关系，可先约定契约并用mock并行开发。

## 技术栈与框架

主要开发语言为JavaScript/JSX。前台React 19.2.0 + Vite 6.4.2；服务端Node.js >=22 ES Modules，模型通过server/llm-client.mjs调用兼容Chat Completions的接口。当前前台取完整JSON，流式是P1新增目标。统一规划及表达改进优先在现有Node引擎完成；Python LangGraph是P2可选项，不需要为完成P0先迁移框架。

完整版本、启用状态、接口约定和阶段安排见[技术栈与共同开发约定](技术栈与共同开发约定.md)。不得擅自重写共用路由、升级框架或更换存储。

建议回归命令：`npm run test:turn-planning`；`npm run test:presales-dialogue`；`npm run team:verify`。这些是现有入口，不保证覆盖本清单全部要求；每条必须追加其特有的正向、异常和权限用例。真实服务未运行写blocked。

## 详细清单

### A-001 首次进入及会话恢复

**优先级：P0｜模块：前台会话｜初始状态：待逐项核验**

作为咨询客户，我希望刷新后继续原来的咨询，以便不用重复讲述需求。

**复现/验收场景：** 先问热玛吉并留下一条消息，再刷新；另一浏览器新开咨询。

**验收条件：**

- AC1（`TC-A-001-AC1`）：首次进入仅出现一次AI身份说明与欢迎语。
- AC2（`TC-A-001-AC2`）：刷新后恢复服务端确认的会话与消息顺序，未发送草稿不自动发送。
- AC3（`TC-A-001-AC3`）：另一浏览器不能仅通过替换session_id读取原会话。
- AC4（`TC-A-001-AC4`）：恢复失败明确提供重试或新建入口，不把旧消息挂到新客户。

**异常与边界：** 会话凭据过期时清理失效绑定；历史加载失败不显示“没有历史”。

**开发拆解：**

1. 梳理session_id/session_token与Cookie的用途。
2. 实现恢复中、成功、失效三种页面状态。
3. 与B核对历史消息回读契约。

**代码入口与修改归属：**

- `apps/acquisition-advisor/src/App.jsx`（A）。
- `server/acquisition-session.mjs`（A）。

**协作/验收依赖：** B-003, B-004

**交付证据：** 在报告中记录`A-001`、4项AC的pass/fail/blocked、实际提交号、测试或浏览器证据路径。涉及UI记录实际点击操作，涉及业务成功附脱敏服务端回执；mock和真实联调分开。

### A-002 连续输入、键盘发送与焦点

**优先级：P0｜模块：前台会话｜初始状态：待逐项核验**

作为咨询客户，我希望连续发送咨询时输入框保持可用，以便无需每轮重新点击。

**复现/验收场景：** 连续三轮键盘发送；中文输入法候选词确认；鼠标点击发送；手动切到资料按钮。

**验收条件：**

- AC1（`TC-A-002-AC1`）：键盘发送和回复结束后可继续输入，草稿不因消息更新丢失。
- AC2（`TC-A-002-AC2`）：中文组合输入的Enter不误发，Shift+Enter换行。
- AC3（`TC-A-002-AC3`）：空白内容不发送，连点不触发重复请求。
- AC4（`TC-A-002-AC4`）：用户主动移到其他控件时不强行抢回焦点，按钮有发送中状态。

**异常与边界：** 请求失败保留可恢复的原文；页面卸载不执行失效focus。

**开发拆解：**

1. 分离草稿与消息状态。
2. 处理composition事件与发送锁。
3. 补齐焦点、键盘和鼠标三组浏览器步骤。

**代码入口与修改归属：**

- `apps/acquisition-advisor/src/App.jsx`（A）。

### A-003 消息状态与重复提交

**优先级：P0｜模块：前台会话｜初始状态：待逐项核验**

作为咨询客户，我希望区分发送中、成功和失败，以便知道消息是否真正送达。

**复现/验收场景：** 弱网下连点发送并重试同一条“我想面诊”。

**验收条件：**

- AC1（`TC-A-003-AC1`）：用户消息有稳定客户端消息标识并与服务端回执关联。
- AC2（`TC-A-003-AC2`）：重试同一消息不增加重复对话、客户或预约记录。
- AC3（`TC-A-003-AC3`）：失败消息可以重试，成功回执到达后只更新原消息。
- AC4（`TC-A-003-AC4`）：消息状态以服务端确认结果为准，不用本地添加气泡表示业务成功。

**异常与边界：** 超时但服务端已提交时先按同一标识查询/重试；具体协议与B共同冻结。

**开发拆解：**

1. 新增或复用client_message_id映射。

作为咨询客户，我希望停止长时间等待并继续提问，以便不中断后续咨询。
