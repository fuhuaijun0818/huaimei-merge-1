# 共享代码接入点与协作顺序

V2没有重构业务大文件，避免在工具包中混入未经验收的页面改造。本说明提供现有接入点；新增独立模块由对应开发者在首批任务中渐进抽取。最终归属继续以handoff/ownership.json为准。

|---|---|---|---|

## 共享改动操作规则

1. 先在任务报告列明共享文件、要变更的函数/接口以及影响方。
2. 抽取业务模块与改变业务行为尽量分成不同提交；抽取后先跑原测试。
3. 同一轮只由一人修改同一注册点；其余人使用适配函数或Mock先开发，由负责人合入后同步。
4. 接口新增保持兼容；字段重命名、状态含义或认证变化先记录在契约变更模板并通知消费方。
5. 新文件路径在ownership没有分配时按共享申报。本工具包devkit、tests/onboarding、contracts/dev-v2统一负责人维护，避免三人各改出不同Mock。

首批无需重写整个后台：先抽离正在修复的客户/接待或知识区域。每次只检查一次事件绑定、清理函数及渲染副作用，防止重复绑定造成按钮二次执行。
