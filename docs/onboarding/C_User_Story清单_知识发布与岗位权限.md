先完成资料版本、审核与正式发布到实际问答生效/撤回闭环，同时把账号、菜单、接口与对象权限逐层验收。图检索升级不阻塞本轮发布正确性。

每条均为目标验收要求，不代表当前全部未实现。先运行/复现并记录“已有通过、需修复、需新增、受阻”；已有能力应复用。AC1～AC4是独立验收点，代码入口是本次核对存在的定位参考，不表示该功能已完整实现。协作依赖含联合验收关系，可先约定契约并用mock并行开发。

## 技术栈与框架

后台原生JavaScript与Node.js >=22 ES Modules；资料对象使用现有ali-oss 6.23.0/本地适配；数据库使用pg 8.23.0、SQL迁移及RLS。默认知识检索为Node本地哈希向量加词项匹配；GraphRAG 3.1.1 + FastAPI为可选Python服务且基线关闭。五岗位和超级管理员沿用src/role-catalog.js。

完整版本、启用状态、接口约定和阶段安排见[技术栈与共同开发约定](技术栈与共同开发约定.md)。不得擅自重写共用路由、升级框架或更换存储。

### C-001 知识、发布与人员页面入口

**优先级：P0｜模块：后台入口｜初始状态：待逐项核验**

作为内容与管理人员，我希望进入职责对应的页面，以便完成资料和账号操作。

**复现/验收场景：** 内容专员打开资料页，发布人员打开发布页，管理员打开人员页。

**验收条件：**

- AC1（`TC-C-001-AC1`）：各岗位显示正确菜单且可实际进入。
- AC2（`TC-C-001-AC2`）：直接访问深链接按权限返回页面或明确拒绝。
- AC3（`TC-C-001-AC3`）：加载、空数据、失败重试三态完整。
- AC4（`TC-C-001-AC4`）：页面刷新和返回不丢失有效筛选，不出现不可点击遮罩。

**异常与边界：** 401统一转登录，403保留明确权限说明；不显示假成功空页。

**开发拆解：**

1. 核对路由和按钮事件。
2. 按ownership约定抽离knowledge/administration模块。
3. 逐岗位浏览器验证。

**优先级：P0｜模块：资料入库｜初始状态：待逐项核验**

**验收条件：**

**异常与边界：** 重复完成请求幂等；不完整对象不得进入候选包。
