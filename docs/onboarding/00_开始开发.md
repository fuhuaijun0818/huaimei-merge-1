# 开发启动与联调包 V2

从本包 `huamei-baseline-v2.bundle` 克隆完整项目，以 `team-baseline-20260910-v2` 创建个人分支。本版在V1代码之上新增开发工具及说明，没有改写业务模块。V1标签保留。Story文档沿用原编号和V1核对记录，新工具及交接信息以本目录V2说明为准。

可先执行 `npm run team:bootstrap` 一次完成依赖安装、构建、Mock账号生成和环境检查；下方列出等价分步流程。该命令需要可用npm源，失败即停止，不清空已有账号。

## 第一天顺序

1. 阅读自己的Story、01现状与首批任务、02环境配置、03接口联调、04共享接入点。
2. `npm ci`，`npm --prefix apps/acquisition-advisor ci`，`npm run team:build`。
3. `npm run team:seed`：创建本机Mock数据和12个随机账号；密码仅写入被忽略的`.team-dev/accounts.private.json`。
4. `npm run team:doctor`检查依赖；`npm run team:test:mock`核验Mock契约；`npm run team:test:http`在临时副本测试真实应用HTTP链路。
5. 自己运行应用：`npm run team:init`生成本机单账号开发配置，`npm run dev`打开4173前后台。
6. 需要Mock时另开终端`npm run team:mock`，访问4390；它是独立契约演练服务，不是实际管理后台，也不能仅换API_BASE_URL即替代完整BFF。

## 三种环境不要混用

| 环境 | 账号与数据 | 已覆盖 | 未覆盖 |
|---|---|---|---|
| Mock 4390 | 两个模拟租户、每租户六角色、六会话、四资料、按测试创建预约 | 协作状态、回执、幂等、冲突、权限与失败演练 | 正式业务实现、真实模型、院方接口、SSE推送、完整RLS |
| 真实本机4173/4180 | team:init单个本机管理员；自己的local_json | 现有页面、真实Node服务及已实现链路 | 完整多岗位数据库权限、正式发布证据与外部服务 |
| 隔离PostgreSQL开发库 | 新seed脚本可创建12账号；必须先完成迁移 | 为真实多角色测试准备账号 | 本轮未实际连接数据库验收，不预置完整真实业务库 |

## 常用操作

- 重置Mock：停止Mock后执行`npm run team:seed -- --reset`，再启动；旧随机密码和会话失效。只操作.team-dev，不碰真实应用数据。
- Mock与真实HTTP测试各自创建临时目录，结束后清理，不读取个人.env.local。
- 原13组核心测试：`npm run team:verify`。新工具报告在.team-dev，提交时仅附脱敏测试报告，不能提交账号文件或状态库。
- 按原team:deliver交付，角色、任务号、Story ID和AC结果写入报告。V2增量必须在V2集成仓库接收；V1交回代码留在V1验收后由负责人迁移，不强行改标签。
