# 环境、账号和外部服务配置

版本事实见原《技术栈与共同开发约定》。Node >=22、Git、npm为基础；React/Vite及pg等按锁文件安装。Python只在编排或GraphRAG任务启用时分别建虚拟环境，不是前三人核心任务的启动前提。

## 所需服务与配置

| 人员 | 开始工作所需 | 联调时增加 | 配置验证 |
|---|---|---|---|
| A | 真实本机应用、公开知识子集、B/C Mock | 经授权的开发模型 | LLM_ENABLED、BASE_URL、MODEL、API_KEY及数据出站准入；完整变量说明查.env.example，禁止仅开开关就宣称接通 |
| B | 真实Node服务、Mock账号与业务样例 | 独立PostgreSQL、院方测试配置 | 会员URL、AUTH_MODE=none、AKEY、RESULT_SEMANTICS=duplicate_only、OPERATION=read_only等按适配器校验 |
| C | 公开知识子集、发布权限Mock | 独立PostgreSQL及测试对象存储；可选索引服务 | 实际租户/科室、文件权限、发布版本、数据库及对象存储就绪 |

真实密钥由负责人单独通过约定的私密渠道发放，不放ZIP、Git、截图或普通日志。没有配置时使用Mock并标blocked；不复制生产账号给多人共享。

## 端口与数据隔离

- 真实应用默认4173/4180，Mock默认4390。Mock端口可用HUAMEI_TEAM_MOCK_PORT修改，但只绑定127.0.0.1。
- team:test:http在临时目录和随机本机端口启动，LLM/院方/GraphRAG/外发均关闭。
- 真实应用换端口需同步PORT、HUAMEI_ACQUISITION_SERVICE_PORT/URL、HUAMEI_ALLOWED_ORIGINS。Origin错误403不能通过删除校验解决。
- .team-dev为Mock与工具报告；.local-data为应用状态。不要互相复制，也不要直接清空对方的目录。

## 多岗位真实数据库账号

1. 用独立开发实例建立名称以`huamei_team_dev`开头的数据库，完成项目全部迁移。PostgreSQL 16的本机Compose模板在deploy/local/compose.yml；该模板默认库名并非安全seed脚本允许的名字，必须自行为独立开发实例调整。
2. 在本机设置`HUAMEI_TEAM_SEED_DATABASE_URL`，仅localhost/127.0.0.1/::1目标可用；不得指向现有业务库。管理员迁移凭据与应用运行凭据分开。
3. 执行`npm run team:seed:postgres`只预览；核对目标后`npm run team:seed:postgres -- --apply`。
4. 脚本仅创建标记为devkit_seed=v2的team_alpha/team_beta模拟租户及12账号。遇到同名非本工具租户拒绝覆盖；事务失败回滚；重复执行会更新这些测试账号密码/版本。
5. 密码沿用本机Mock账号文件。应用切换PostgreSQL后，按现有认证、可信租户绑定及岗位配置登录验证；不能在前端随意传tenant_id切换机构。

本轮没有运行真实数据库seed或RLS集成验收；该项在验证记录中标blocked。完整客户、会话、预约和资料库的数据库造数应走对应业务API及隔离集成测试，不用伪造生产表插入脚本替代。

## 院方接口特别说明

院方已确认查询无需验签，但代码仍校验AKEY、指定endpoint和duplicate_only/read_only语义；这与“需要secret”不同。不要为了本地Mock而修改真实适配器的endpoint限制。Mock会员接口独立模拟true/false/error/invalid；真实适配器测试可用注入fetch的既有测试方式。公开留资接口仅给脱敏保存回执，查重结果只给有权限的后台使用。

## 常见问题

| 现象 | 排查 |
|---|---|
| 首页可开但API403 | 检查Origin、实际端口及权限；不是直接关鉴权 |
| 页面404或旧资源 | 重新team:build；确认启动的是自己的副本 |
| 模型回答固定 | 检查LLM开关与真实调用证据；Mock/本地兜底不代表模型接通 |
| Mock账号不能登录4173 | 两个独立环境；先按上述数据库步骤配置真实账号 |
| seed失败 | 检查库名、loopback、迁移、租户标记与数据库权限 |
| 发布按钮可点但答案没变 | 检查激活版本、实例加载、索引与缓存；不能只看按钮回执 |
