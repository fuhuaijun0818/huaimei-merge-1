# 联合验收与交付节奏

## 自动化入口

| 命令 | 本轮可运行范围 | 报告 |
|---|---|---|
| npm run team:test:mock | 独立Mock登录、两租户、消息幂等、接管、查重、预约及发布状态 | .team-dev/mock-test-report.json |
| npm run team:test:http | 真实Node应用临时副本：页面HTTP、登录登出、两轮项目追问、留资、后台同会话 | .team-dev/application-http-report.json |
| npm run team:verify | V1已有13组核心回归 | 控制台结果，提交时保存脱敏记录 |
| npm run team:seed:postgres | 仅预览数据库账号计划；--apply才写入指定本机开发库 | 控制台目标摘要；不打印密码 |

Mock只验证目标协作约定，不代表真实模块已完成。HTTP测试不驱动浏览器，不能证明所有按钮、焦点、未读和滚动已正确。

## 必须补充的浏览器联合旅程

| 编号/负责人 | 具体步骤 | 预期与证据 |
|---|---|---|
| E2E-01 A+B | 两个访客咨询，后台停留客户甲并编辑草稿，客户乙继续发言 | 两条独立会话；乙红点增加；甲草稿/焦点不变；记录两个会话ID及前后台截图 |
| E2E-02 A+B | 热玛吉→一般原理→主动留资并问价→拒绝联系 | 主题延续；保存回执；不暴露查重；不重复索号或催约；记录run/receipt与脱敏答复 |
| E2E-03 A+B | AI生成时人工领取→发送→重连→恢复AI | 无迟到AI抢答；人工原窗口送达一次；状态版本一致；记录竞态时序 |
| E2E-04 A+B | 确认登记→重复提交→改期冲突→刷新后改期→取消 | 同一登记ID；无重复创建；版本正确；不宣称医生名额已锁定 |
| E2E-05 A+C | 上传→审核→候选→评测→激活→前台问→撤回→再次问 | 实际引用对应版本；撤回后不再使用；双实例/缓存记录 |
| E2E-06 B+C | 六角色、两个租户分别访问客户详情/发消息/看电话/发布/管账号 | 允许与拒绝符合真实权限矩阵；不能拿Mock矩阵冒充RLS结果 |
| E2E-07 全员 | 登录过期、退出、多标签页、浏览器返回与未保存表单 | 旧会话失效、停止轮询；草稿不跨账号；未确认写操作不自动重放 |

执行模板在contracts/dev-v2/acceptance-template.json。每项填写pass/fail/blocked、环境、Story ID、实际与预期、接口/界面证据及版本。

## 每轮节奏

1. 负责人确认首批任务与契约；A/B/C各自提交现状复现结论。
2. 每1～2个工作日交可运行增量，不能等整份Story全部完成再交。
3. 共享入口/协议/迁移变化先单独审查合入；消费方同步后联调。
4. 单模块通过后执行相关E2E；失败回到对应Story，不用新增另一套绕过逻辑。
5. 负责人先team:inspect验证包，再在独立分支测试整合；只将实际通过的项标通过。

没有真实模型、院方、数据库或正式资料时列blocked及所缺配置；不把演练结果写成生产验收。
