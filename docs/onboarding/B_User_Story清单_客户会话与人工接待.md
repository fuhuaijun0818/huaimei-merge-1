## 阅读与执行

前后台同会话、只刷新相关区域、未读红点、人工实际送达及接管竞态优先。手机号格式通过即保存，会员查询失败不能丢失客户。

每条均为目标验收要求，不代表当前全部未实现。先运行/复现并记录“已有通过、需修复、需新增、受阻”；已有能力应复用。AC1～AC4是独立验收点，代码入口是本次核对存在的定位参考，不表示该功能已完整实现。协作依赖含联合验收关系，可先约定契约并用mock并行开发。

## 技术栈与框架

后台使用原生JavaScript ES Modules、HTML/CSS及hash路由；服务端Node.js >=22原生HTTP。当前SSE/EventSource和退避轮询并存。存储开发模式为local_json，正式适配使用pg 8.23.0与PostgreSQL，Redis用于已有基础设施能力。修改React前台的人工消息展示由A协作，不另建聊天系统。

完整版本、启用状态、接口约定和阶段安排见[技术栈与共同开发约定](技术栈与共同开发约定.md)。不得擅自重写共用路由、升级框架或更换存储。

建议回归命令：`npm run test:member-check`；`npm run test:acquisition-orchestration`；`npm run team:verify`。这些是现有入口，不保证覆盖本清单全部要求；每条必须追加其特有的正向、异常和权限用例。真实服务未运行写blocked。

### B-001 客户与接待菜单可进入

**优先级：P0｜模块：后台入口｜初始状态：待逐项核验**

作为售前顾问，我希望进入自己有权限的业务页面，以便开始接待和跟进。

**复现/验收场景：** 登录后点击客户管理、会话与接待、预约列表，再刷新深链接。

**验收条件：**

- AC1（`TC-B-001-AC1`）：有权限菜单可点击，路由与页面标题一致。
- AC2（`TC-B-001-AC2`）：刷新和浏览器前进后退保留有效路由。
- AC3（`TC-B-001-AC3`）：无权限页面显示明确拒绝或可访问入口，不出现空白页。
- AC4（`TC-B-001-AC4`）：页面初始加载、空列表、失败重试分别呈现。

**异常与边界：** 登录过期交由C统一处理，不把401当空数据。

**开发拆解：**

1. 核查现有路由及事件绑定。
2. 将页面逻辑逐步抽到独立业务模块。
3. 为三个入口记录浏览器验收步骤。

**验收条件：**
