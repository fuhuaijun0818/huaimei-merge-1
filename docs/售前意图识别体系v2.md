# 售前意图识别体系 v2

版本：2.0.0  
适用智能体：A-01 AI获客顾问·小美  
目标：在相同服务水平标准下，通过更稳定的自动识别、检索与回答，减少售前人员在重复咨询中的付出时间。

## 1. 设计原则

1. 当前轮优先：当前消息中的明确项目、医生和动作覆盖历史兴趣，避免上一轮主题污染本轮判断。
2. 安全优先：医疗异常、个体适用性、隐私客诉、安全攻击和人工请求先于业务意图执行。
3. 实体与动作分离：“李健院长”是医生实体，“介绍、比较、查排班、预约”是对话动作，两者组合形成最终意图。
4. 先验证证据再回答：每个意图绑定固定证据路线；没有对应证据时澄清或请求人工核验，不使用相似但无关的资料补答。
5. 大模型不改路由：大模型只负责在已确定意图、实体和证据范围内改善表达，不能重新解释意图或替换证据。

## 2. 识别流程

用户消息依次经过：

1. 确定性安全门禁；
2. 项目、医生、科室、关注问题和部位实体链接；
3. 介绍、比较、推荐、价格、政策、核验、排班、预约、导航、服务、案例等对话动作识别；
4. 规则分、原型相似度和证据可用性联合评分；
5. 当前轮与多轮上下文冲突消解；
6. 置信度判断与单问题澄清；
7. 按意图路由到项目知识、医生资料、价格政策、目录、预约服务或受限资料边界；
8. 本地答案生成，大模型在边界内润色，输出后再次进行合规检查。

## 3. 意图树与证据路线

| 领域 | 意图 | 证据路线 | 处理动作 |
|---|---|---|---|
| 安全 | medical_emergency / medical_safety / medical_suitability | 不检索 | 紧急接管、医务接管或医生评估 |
| 安全 | privacy_or_complaint / security_or_compliance | 不检索 | 责任团队接管或阻断 |
| 转人工 | human_handover_request | 不检索 | 转人工顾问 |
| 项目 | project_explanation | 审核后的项目知识 | 介绍一般原理与流程 |
| 项目 | project_comparison | 审核后的项目知识 | 按相同维度比较项目 |
| 项目 | project_discovery_by_concern | 审核后的项目知识 | 按关注问题给出项目方向 |
| 医生 | doctor_profile | 医生介绍资料 | 介绍点名医生的资料覆盖方向 |
| 医生 | doctor_discovery_by_project | 医生介绍资料 | 按具体项目提供医生候选 |
| 医生 | doctor_comparison | 医生介绍资料 | 比较两位及以上医生的资料方向 |
| 医生 | doctor_schedule_verification | 医生介绍资料 | 仅确认资料存在，排班交人工实时核验 |
| 商业 | price_verification | 项目价格目录 | 不报历史价，核验当前价格和包含项 |
| 商业 | policy_verification | 政策与权益目录 | 核验有效期、条件和限制 |
| 导航 | directory_discovery | 目录概览 | 展示可咨询资料范围 |
| 转化 | appointment_query / appointment_request | 预约服务 | 收集项目和时间偏好，交人工确认号源 |
| 服务 | service_information | 到院服务信息 | 提供或核验地址、停车、营业时间等 |
| 受限 | case_request_restricted | 仅访问受限元数据 | 不展示案例、照片或客户沟通记录 |
| 会话 | conversation_followup | 已确认上下文 | 延续上一主题 |
| 会话 | need_clarification | 不检索 | 只追问一个关键问题 |

## 4. 关键冲突规则

- 历史在聊“抗衰”，本轮输入“李健院长”：doctor_profile。
- 历史在聊“抗衰”，本轮输入“胸部整形推荐哪个医生”：doctor_discovery_by_project。
- 历史关注“胸部整形”，本轮输入“双眼皮多少钱”：price_verification，并以眼部项目为当前实体。
- 同时出现“政策”和“下面有哪些资料”：directory_discovery，因为用户是在浏览目录，不是在核验政策有效性。
- 同时出现医生姓名和“案例照片”：case_request_restricted，受限资料规则高于医生介绍。
- 点名医生并问“今天出诊吗”：doctor_schedule_verification，不把医生介绍资料当作当前排班。

## 5. 输出与监控字段

每次 A-01 调用在 `structured_data.intent_analysis` 中输出：

- `primary_intent`、`secondary_intents`；
- `domain`、`dialogue_act`；
- 项目、医生、科室、关注问题和部位实体；
- `confidence`、`confidence_band`；
- `clarification_required`；
- `reason_codes`、候选意图评分；
- `evidence_plan` 与 `next_action`；
- 当前轮是否覆盖上下文、是否使用历史上下文。

公开咨询接口同步返回意图、置信度、领域、对话动作、是否需澄清和已识别医生。管理状态接口返回意图数量、项目别名数、医生实体数及算法版本。

## 6. 质量门禁

自动化评测包括39个专项意图案例、1662个消费者知识问题、132个策划安全样本、396段多轮对话和1143个多轮消息。发布门禁为：

- 意图准确率不低于95%；
- 实体链接准确率不低于95%；
- 澄清判断准确率不低于95%；
- 公共资料目录族召回率不低于80%；
- 确定性风险召回率和紧急首轮接管率不低于95%；
- 不出现价格承诺和内部实现措辞。

评测报告输出到 `artifacts/acquisition-eval-report.json`。人工付出时间下降仍需结合坐席实际分钟数和连续4周同口径基线单独验收。
